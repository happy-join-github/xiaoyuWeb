# 小愈 — 聊聊模块设计哲学

> 本文档阐述"聊聊"（ChatRoom）与"树洞"（Treehole）两个模块的产品定位、设计原则和协作关系。
>
> 这是产品设计文档，不是接口契约。接口文档见 `chat-api.md` 和 `treehole-api.md`。

---

## 核心原则：双 Tab，强差异化

"聊聊"和"树洞"同时出现在底部 TabBar 中，是因为它们解决的是**两种不同的情绪需求**，不是同一功能的两个入口。它们的差异必须从定位到交互到数据层全面贯彻，不能只是换个主题色。

---

## 一、聊聊（ChatRoom）—— AI 伙伴日常陪伴

### 一句话定位

> 我的 AI 伙伴，记得我是谁，记得我们聊过什么。

### 用户心智模型

用户打开"聊聊"时的心理预期是："**找小愈聊聊天**"——就像找朋友聊天一样自然。这是一种**连续的、积累的关系**。

### 设计原则

| 原则 | 说明 |
|------|------|
| **连续性** | AI 记得用户是谁、记得上次聊过什么。"记忆卡片"展示的是真实的对话记忆，不是固定文案。 |
| **关系感** | 随着陪伴天数（companionDays）增长，AI 的语气和熟悉度逐步加深。第一天和第三十天是不一样的。 |
| **日常化** | 聊天气氛轻松日常，话题由用户发起。AI 不主动追问隐私，不刻意制造"深度"氛围。 |
| **个性一致** | AI 的性格（characterTags / characterBio / voice）由用户在设置中配置，对话风格与之匹配。 |

### 交互特性

- 暖色系界面（奶油色 / 暖橙渐变）
- AI 有名字（小愈）、有头像（🌸）、在线状态
- 快捷情绪行：用户快速表达当前感受，AI 据此调整回应
- 输入区含语音、表情、文字三种输入方式
- FAB 急救按钮：用户情绪崩溃时可一键进入 Rescue 页面
- 树洞入口卡片：日常聊天中自然引导到树洞（当话题涉及"不想让人知道"时）

### 数据边界

- 会话持久化存储，支持历史回溯
- 跨会话记忆（AI 记住用户之前提过的话题）
- 会话标题由 AI 根据内容自动生成
- 所有数据与用户身份绑定

## 二、树洞（Treehole）—— 匿名情绪急救

### 一句话定位

> 匿名的、一次性的深度倾诉空间，说完就走，不留痕迹。

### 用户心智模型

用户打开树洞时的心理预期是："**心里堵了，想去树洞待会儿**"——像在深夜找一个没人的角落坐下来。这是一种**一次性的、匿名的情绪释放**。

### 设计原则

| 原则 | 说明 |
|------|------|
| **一次性** | 每次进入树洞都是一次新的会话。离开后不保留对话记录（除非用户主动保存到日记）。 |
| **匿名感** | AI 不称呼用户名字，不关联用户身份。顶部的"🔒 匿名"标签和安全标语是持续的视觉提醒。 |
| **深度共情** | 树洞的 AI 回复比日常聊天更有深度和情感浓度，侧重倾听和接纳，而非解决问题。 |
| **有始有终** | 离场时有收束流程（保存到日记 / 直接离开 / 再待一会儿），避免用户"悄悄消失"。 |
| **氛围沉浸** | 暗色界面、星星动画、月亮发光、可切换的治愈音景——营造"深夜独处"的空间感。 |

### 交互特性

- 暗色界面（深棕渐变 → 深夜更深色）
- AI 无名字，用 🌙 代替头像
- 进入时的智能问候文案（根据深夜/傍晚/白天切换）
- 轮换式输入框 placeholder，引导用户表达
- 3 轮对话后弹出情绪标签选择
- 保存到日记按钮（将对话摘要同步到心情签到模块）
- 离场浮层（三个选项）
- 治愈音景（雨声/篝火/海浪/森林），纯 UI 阶段，后续可接入真实音频

### 数据边界

- 每次进入都是新会话，不保留上次对话
- 情绪标签通过 sessionStorage 桥接至心情签到（MoodCheckin），不会在树洞内持久化
- 仅当用户主动"保存到日记"时，对话摘要才会写入心情记录
- 树洞本身不保留用户身份信息（本质上是匿名会话）

## 三、两个模块的协作关系

### 各自独立的部分

| 维度 | 聊聊（ChatRoom） | 树洞（Treehole） |
|------|-------------------|-------------------|
| 路由 | /chat | /treehole |
| Tab | 聊聊 | 树洞 |
| 主题色 | 暖色系 | 暗色系 |
| AI 身份 | 有名字、有性格 | 匿名、不记名 |
| 记忆 | 跨会话记忆 | 每次新会话 |
| 持久化 | 全部保留 | 不留（除非主动保存） |
| 情绪标签 | 无 | 有（3 轮后触发） |
| 离场流程 | 无特殊处理 | 有收束浮层 |
| AI 语气 | 日常陪伴 | 深度共情 |

### 共享的部分

- **消息结构（Message）**：双方共用 `{ id, role, content, time }` 结构，定义在 `src/api/mock.ts`
- **AI 回复引擎**：`src/views/treehole/aiReply.ts` 提供 `getAiReply()`，ChatRoom 和 Treehole 共同引用。当前为关键词匹配引擎，后续可统一替换为真实 AI 接口
- **共享存储层**：`src/utils/chatStorage.ts` 提供基于 localStorage 的会话 + 消息 CRUD，两个模块共用同一套存储结构，通过 `type: "chat" | "treehole"` 区分
- **聊天历史列表（ChatHistory）**：从共享存储层读取所有会话记录，用标签区分类型（树洞 / 日常），让用户看到完整的情绪轨迹
- **底层会话模型**：如果接入后端，`POST /api/chat/sessions` 用 `type: "chat"` / `type: "treehole"` 区分，其余接口复用

### 聊到树洞的引导路径

```
ChatRoom 中用户表达 "不想让人知道"
    → 记忆卡片区出现树洞入口卡（"匿名倾诉"）
    → 点击进入 Treehole
    → 树洞离场时可选择保存到日记
    → 日记在 MoodCheckin 中体现
```

这条路径不是强制跳转，是自然引导。ChatRoom 保留树洞入口卡，但不主动推送。

### 共享但不混淆

ChatHistory 是**唯一同时展示两个模块的地方**。设计上要求：
- 每条记录清晰标注类型标签（"树洞" / 无标签即日常聊天）
- 树洞记录显示 🌙 图标，日常聊天显示 🌸 图标
- 点击树洞记录进入 Treehole 的新会话（不恢复旧对话）
- 点击日常聊天记录进入 ChatRoom 的对应会话

## 四、为什么需要两个模块，而不是一个

用户在"小愈"中同时拥有日常陪伴和匿名倾诉，不是因为技术做不到合二为一，而是因为**人的情绪需求本身就是两种不同的模式**：

- 有些时候你想被记住、被了解、被长期陪伴——这是"聊聊"
- 有些时候你只想在一个没人知道你是谁的地方，把话说出来——这是"树洞"

两个模式服务于同一个人，但在不同时刻、不同心境下。产品设计尊重这种差异，不强行统一。

## 五、后续演进方向

### 已实施（P0）

- ✅ ChatRoom 接入消息发送 + AI 回复（共用 `getAiReply`）
- ✅ ChatRoom 快捷情绪行绑定真实行为
- ✅ ChatRoom 消息持久化（localStorage，`src/utils/chatStorage.ts`）
- ✅ ChatHistory 从存储层动态渲染 + 搜索过滤

### 规划中

1. **Treehole 情绪双记录**：进入时选一次当前情绪，离开时再选一次，展示"倾诉前后的情绪变化"，这本身就是一种治愈反馈。

2. **Treehole 音景接入真实音频**：当前音景切换只是 UI 状态变化，后续可集成 Web Audio / 音频文件播放。

3. **ChatRoom AI 记忆系统**：短期用 localStorage 做会话内关键词累积，长期接入后端实现跨会话话题记忆。

4. **ChatRoom AI 语气随陪伴天数渐变**：companionDays 映射到 AI 回复风格参数，让关系感随时间自然增长。

5. **Treehole 接入共享存储层**：当前 Treehole 的消息和情绪标签使用独立的 sessionStorage，后续可统一接入 `chatStorage.ts`，使树洞会话也能出现在 ChatHistory 中。
